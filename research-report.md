# Second Life Open-Source Coding Ecosystem — Research Report

## Summary

**Confidence / basis:** High for the core stack verified live on GitHub on **2026-11-23** (`secondlife/viewer`, `FirestormViewer/phoenix-firestorm`, `AlchemyViewer/Alchemy`, `cinderblocks/libremetaverse`, `openmetaversefoundation/libopenmetaverse`, `opensim/opensim`, `radegastdev/radegast`, `singularity-viewer/SingularityViewer`, `secondlife/autobuild`, `Kaleaon/Lumiya-Redux`, `secondlife` org list). Medium / `index`-only for wikis, LSL tooling, OpenSim forks, JS/Go LLSD, and legacy clients — wikis are frequently stale (many pages last edited 2014–2024) and several TPVs have **no canonical GitHub repo** (Catznip, Kokua, Cool VL, Black Dragon — see §2 / Could not verify).

**The one-sentence map:** All graphical viewers are forks of one C++ codebase — Linden Lab `secondlife/viewer` (LGPL-2.1, `indra/`, Autobuild/CMake) — speaking (a) a legacy **UDP message system** defined by `message_template.msg`, and (b) **HTTPS capabilities (caps)** returning **LLSD**, to either Linden Lab's closed simulator or the open **OpenSimulator** (C#, BSD). The only actively maintained, reusable *client library* is **LibreMetaverse** (C#/.NET, BSD-3). That is why a mobile viewer in TypeScript + Kotlin/Java + C# should treat: `secondlife/viewer` = normative protocol/render truth, `secondlife/master-message-template` + `lsl-definitions` = generated-code truth, LibreMetaverse = reusable protocol implementation to port/copy semantics from, OpenSimulator = test server you can run/debug locally, and the SL Wiki caps/LSL pages = human-readable (but dated) spec.

**Licence warning that shapes all reuse:** Viewer code is **LGPL-2.1** (not GPL for the library parts, not permissive) — TPV derivatives must stay LGPL-compatible and comply with Linden Lab's TPV Policy. LibreMetaverse / OpenSim are **BSD**, Radegast is BSD-style, Lumiya-Redux recovery is Apache-2.0, LSL-PyOptimizer is GPL-3 — do not mix GPL-3 optimizer code into an LGPL/permissive client without legal review. Kakadu (JPEG2000) and Havok and Vivox/SLVoice are **proprietary, closed** — open viewers substitute OpenJPEG and Bullet/ODE and (now) WebRTC.

**Login (cross-cutting, from wiki + Lumiya-Redux docs, *index*):** Legacy login is XML-RPC (now also LLSD variants) `POST https://login.agni.lindenlab.com/cgi-bin/login.cgi` (Agni) / Aditi beta grid equivalent — request: first/last (or username), `$1$`+MD5(password) historically, start location, viewer channel/version, MAC/id0 etc.; response LLSD map: `agent_id`, `session_id`, `secure_session_id`, `sim_ip/sim_port`, `circuit_code`, `seed_capability`, inventory skeleton, buddy list, `login-flags`. Then: POST cap names (LLSD array) to the **seed capability** → map of cap name→unguessable `https://sim…/cap/<uuid>` URLs; send UDP `UseCircuitCode` + `CompleteAgentMovement`; start Event Queue long-poll. Pitfalls: password hashing/login options have gained MFA/token variants — read current `llstartup`/login code in viewer and LibreMetaverse `Login` (`LibreMetaverse.Protocol` login request/response in new split), not 2008 PyOGP strawman pages (https://wiki.secondlife.com/w/index.php?title=Pyogp/Protocols&oldid=77681 describes the abandoned OGP/agent-domain flow, **not** production login).

### 5. Scripting — LSL / OSSL / SLua

**LSL language model (what a skill must encode):**
- **State machine is the language:** a script is `default { state_entry(){…} event handlers… }` plus named `state X;` transitions (`state_entry`/`state_exit` on every transition). No threads, no main(), event-queue driven, single-threaded cooperative. Types: `integer` (32-bit, also bool), `float`, `string`, `key` (UUID), `vector` (3×float), `rotation` (quaternion 4×float), `list` (heterogeneous, no arrays/structs). Memory: Mono scripts 64KB (legacy LSO 16KB) — string/list operations dominate OOM bugs. Delays: many `ll*` calls impose script delays (e.g. `llSay` family, `llSetPrimitiveParams` 0.2s historically) and throttle limits per object/parcel.
- **Events (~40):** `state_entry/exit, touch(_start/_end), collision(_start/_end), listen, sensor/no_sensor, timer, money, attach, changed, http_request/http_response, dataserver, link_message, moving_start/end, object_rez, on_rez, remote_data` (legacy XML-RPC), `run_time_permissions, control, at_target/not_at_target, at_rot_target/not_at_rot_target, land_collision*, email, experience_*` — full signatures in `secondlife/lsl-definitions` and Category:LSL Keywords (https://wiki.secondlife.com/w/index.php?title=Category:LSL_Keywords/All, *index*).
- **Functions (~570 `ll*`):** canonical docs = **LSL Portal** `wiki.secondlife.com/wiki/LSL_Portal` → per-function pages (signature, delay, energy, caveats, examples). Machine-readable truth = `lsl-definitions` (§1). **Do not scrape the wiki for signatures when the YAML exists.**
- **Execution in SL:** scripts compile server-side to **Mono** bytecode (legacy LSO on old regions); source is an inventory asset, compiled asset is separate. Permissions system (`run_time_permissions`: PERMISSION_DEBIT/TELEPORT/ATTACH/TAKE_CONTROLS/CHANGE_LINKS…) gates sensitive calls — missing-permission silent failures are the #1 LSL bug class.
- **Firestorm/TPV preprocessor:** in-viewer editing adds C-preprocessor (`#include "file.lsl"`, `#define`), Boost.Wave/mcpp, plus extensions: `switch()`, lazy list indexing `list[i]`, duplicate function definitions, and a simple unused-global stripper. **Code written with these does not compile in the stock LL editor/OpenSim without preprocessing** — a skill must detect and expand them.

**OpenSim scripting — differences that break ported scripts:**
- Engines: **XEngine** (legacy, AppDomain loading, expression evaluation order historically *opposite* to SL in places, `llSleep` can stall) vs **YEngine** (current, from XMREngine: microthreading, state saving, SL-like evaluation order, better `llSleep`) — config `[YEngine]`/`[XEngine]` in OpenSim.ini; SL has neither.
- **OSSL:** `os*` functions (`osTeleportAgent, osNpcCreate, osSetDynamicTextureURL, osSetDynamicTextureData…`, ~200+) gated by **threat levels** (None→Severe) + `osslEnable.ini` allow-lists per owner/estate/parcel — a script that works for an estate owner silently fails for others. Plus `mod*` (modSendCommand) and LightShare `wl*`. None exist on Agni.
- Behavioural diffs: timer resolution, sensor limits, prim/link limits, `ll*` edge cases and JSON (`llJson*` — Aurora's implementation was found "plain wrong" vs SL by OpenSim devs, mailing-list *index*) — **test every non-trivial script on both a local OpenSim and Aditi**.
- C# scripting was historically available in OpenSim XEngine — disabled/unsafe, do not rely on it.

**SLua (new):** `secondlife/slua` (Luau fork, §1) + `slua_definitions.yaml` in lsl-definitions + official VS Code plugin. Treat LSL skills as legacy-stable and SLua as the growth path; tooling (PyOptimizer, lslint) does not cover SLua.

### 6. Assets & content pipeline

- **Prims:** parametric CSG-ish objects (cube/sphere/prism/torus/tube/ring + sculpt) described by `PrimitiveParams` / `ObjectUpdate` fields (profile/hollow/twist/taper/shear/path cuts). Code: viewer `llprim*`/`llvolume*`, LibreMetaverse `Prim` + `PrimMesher`/`MeshFoundry`, OpenSim `SceneObjectPart`. Pitfall: prim params are packed/bit-fielded differently in UDP vs LLSD vs internal forms — copy a codec, don't reinvent.
- **Sculpties:** shape encoded as a texture (RGB = XYZ vertex map, fixed topology grids e.g. 32×32); viewer/OpenSim tessellate it. Legacy — new content should be mesh.
- **Mesh:** upload = **Collada `.dae`** (Blender exporter) → viewer uploader (`indra/newview/llmeshrepository.cpp` + model loader: LODs High/Med/Low/Lowest, physics shape (convex decomposition/HACD), skin weights, land-impact calculation) → server stores **LLMesh** binary (internal format, header + LOD/physics/skin sections, gzip-ish) fetched via `GetMesh/GetMesh2` caps. LibreMetaverse equivalents: `.ModelFormats` (Collada/glTF/OBJ in, glTF/OBJ/Collada out) + `.Rendering.MeshFoundry`. **glTF is import/export + PBR source format, not the wire/storage format.**
- **Materials / PBR:** legacy = diffuse/normal/specular textures + shininess; current = **glTF 2.0 PBR materials** (baseColor/metallic-roughness/normal/emissive/occlusion, `LLGLTFMaterial` as an inventory asset type, override via prim params / `RenderMaterials` cap area in viewer). EEP (Environmental Enhancement Project) replaced Windlight: environment/day-cycle assets (sky/water/day settings as inventory assets, `EnvironmentSettings`/`ExtEnvironment` caps + parcel environment). **Bakes on Mesh (BoM):** server-side compositing of system-avatar texture layers onto mesh bodies (wearable bake channels, universal wearables) — client must send/appearance-manage correctly or avatars bake grey. **Animesh:** rigged mesh objects animated as pseudo-avatars (AnimatedObject UDP/params). All four are viewer-code-first features — wiki pages lag the `indra/newview` implementations by years.
- **Textures:** **JPEG 2000 codestream (J2C)** — proprietary Kakadu in LL builds, **OpenJPEG** in open builds (viewer `llimagej2c*`, `3p-openjpeg`/`3p-kakadu` distinction; LibreMetaverse CSJ2K lineage; Lumiya's ancient OpenJPEG 1.5 native lib). Discard-level/LOD progressive decode drives texture fetch priority (`GetTexture` HTTP cap with range requests, replacing UDP image packets). Pitfall: OpenJPEG vs Kakadu differ in partial-decode artefacts/speed (Cool VL maintainer's patched-1.5 claim, §2) — visual diffs across viewers are often *codec*, not data.
- **Inventory & assets:** every asset/inventory item is a **UUID** (`asset_id` ≠ `item_id` ≠ `folder_id`); asset types + inventory types are separate enums (LibreMetaverse.Types/Assets, viewer `llassettype.h`/`llinventorytype.h` — keep them in sync from viewer headers). Upload paths: legacy UDP `AssetUploadRequest` vs caps `NewFileAgentInventory`, `Update*InventoryItem` caps, **AIS3** (§7). Asset server is HTTP (X-SecondLife-* headers historically); missing/truncated asset = grey texture / "missing asset" — log UUID + cap URL, not names.
- **Blender pipeline:** Blender (Collada export, metric units scale 1.0, LOD + physics meshes) → optional **Avastar** (paid, Machinimatrix — SL armature/weighting/Bento bones, successor to Primstar-2 for mesh) / **Primstar** (paid/free legacy, sculpties, Blender 2.4–2.6 era, unmaintained) → Build ▸ Upload ▸ Mesh Model in viewer, test on **Aditi** first (free uploads there in practice for testing; uploads cost L$ on Agni). Avastar/Primstar are **closed paid addons, not GitHub projects** — no canonical repo was verified; vendor site is machinimatrix.org (referenced in SL forum posts, *index*).

### 7. Protocol deep dive

**Two planes, always both:**
1. **UDP (simulator circuit)** — `indra/llmessage/` in viewer, `LibreMetaverse.Transport+.Protocol`, OpenSim `ClientStack/Linden/UDP`, Lumiya's 477 generated message classes.
   - Packet: 6-byte header (flags, sequence U32, extra header length) + message ID by frequency (High: 1 byte, Medium: 2, Low: 4 (`0xFFFF`+U16), Fixed: 4) + appended ACKs. Flags: `0x80` Zerocoded, `0x40` Reliable, `0x20` Resent, `0x10` Ack (appended ack list present).
   - **ZeroDecode/ZeroEncode:** run-length-ish encoding where 0x00 bytes are replaced by `0x00 <count>` — applies *only* to zerocoded messages/blocks and only to the header+body portions specified; the ChatFromViewer counterexample (§1) shows template flags can be wrong — verify per-message in viewer `llmessage` template copy.
   - **Reliability:** reliable messages are resent until ACKed (piggybacked acks or standalone `PacketAck`), unacked queue + resend timers in circuit code; ordering is **not** guaranteed beyond per-message handling — object updates are treated as latest-wins. Throttling: per-category token buckets (resend/texture/land/wind/cloud/task/asset, `AgentThrottle` / throttle caps) — mobile clients on lossy links must implement circuit ping (`StartPingCheck`/`CompletePingCheck`), timeout, and `LogoutRequest`/`CloseCircuit` correctly or they ghost.
   - Key messages: login-adjacent `UseCircuitCode, CompleteAgentMovement, AgentUpdate` (control flags, camera — sent ~continuously), `ObjectUpdate` (full: prim params+extra params), `ImprovedTerseObjectUpdate` (position/velocity/rotation compressed — quantisation is a classic jitter bug source), `ObjectUpdateCompressed/Cached`, `KillObject`, `ChatFromSimulator/ChatFromViewer`, `ImprovedInstantMessage` (IM/groups/offline), `StartLureRequest/Teleport*` (`TeleportStart, TeleportProgress, TeleportFinish, TeleportLocal, TeleportFailed`, cross-region via caps+UDP handoff), `RegionHandshake` (+`RegionHandshakeReply`, sim product/SKU, region flags, water height, terrain detail), `CoarseLocationUpdate` (minimap dots, 16m-quantised, no height beyond coarse), `LayerData` (terrain/wind/cloud patches), `AvatarAnimation, ObjectAnimation`, script dialogs/questions, `RequestObjectPropertiesFamily` etc. — full list only in `message_template.msg`.
2. **HTTPS caps (seed → per-region cap map)** — POST LLSD array of names to seed cap, get LLSD map name→URL. Form: `https://simNNNN.agni.lindenlab.com:PORT/cap/<uuid>`. Authoritative *code* list: `LLViewerRegionImpl::buildCapabilityNames` (`llviewerregion.cpp`) ∪ `AISAPI::getCapNames` (`llaisapi.cpp`) — exactly the union Lumiya-Redux syncs its `SLCapability` enum against (its docs, *index*). Wiki list: https://wiki.secondlife.com:443/wiki/Current_Sim_Capabilities (rev. 2025-01-14, *index*). Caps a mobile client actually needs first:
   - `EventQueueGet` (+v2) — long-poll LLSD event array (teleport, IM-ish events, inventory offers, group notices, `ChatterBox*`, lures, script control) — poll loop with ack + error-id handling is the heartbeat of a thin client; a stalled EQG looks like a dead session.
   - Inventory: `FetchInventory2, FetchInventoryDescendents2, FetchLib2, FetchLibDescendents2` (HTTP inventory, replaces UDP fetch for most) + **AIS3: `InventoryAPIv3, LibraryAPIv3`** (create/update/remove/link operations as LLSD/REST-ish calls with COF — Current Outfit Folder — versioning via `IncrementCOFVersion`); legacy UDP inventory messages still exist for some ops — check AIS code first.
   - Content: `GetTexture` (HTTP textures, range/LOD), `GetMesh, GetMesh2`, `GetMetadata, GetObjectCost, GetObjectPhysicsData`, `MeshData` (historical), `RenderMaterials`, material/EEP: `EnvironmentSettings, ExtEnvironment`.
   - Agent/social: `AgentPreferences, AgentState, AvatarRenderInfo, CharacterProperties, GetDisplayNames, ChatSessionRequest` (group/conference chat sessions), `GroupAPIv1, GroupMemberData`, friendship accept/decline caps, `HomeLocation, LandResources, Parcel*` (via caps/UDP mix), `MapLayer` (legacy), `ProductInfoRequest`, `RemoteParcelRequest`, `SearchStatRequest`, `ServerReleaseNotes`, `SimConsole`, `SimulatorFeatures` (**critical:** LLSD feature map — mesh upload limits, physics shape types, PBR, voice type — *query it, don't hardcode*), `StartGroupProposal`, `UpdateAgentInformation/Appearance`, `Upload*` (`NewFileAgentInventory`, `InventoryThumbnailUpload`, `UpdateGestureAgentInventory`…), `ViewerStats, ViewerStartAuction`, voice: `VoiceSignalingRequest`, `ProvisionVoiceAccountRequest` (legacy Vivox provisioning).
   - Pitfalls: cap URLs are **per-region, per-session, unguessable and expire on region change/teleport** — never cache across sessions; cap *availability varies by grid/sim version* (OpenSim implements a subset, with different names in places) — always request-and-check, with UDP fallback where viewer has one. LLSD content-type is `application/llsd+xml` (binary LLSD exists for some endpoints).
3. **Voice:** Legacy = **Vivox**: viewer spawns closed `SLVoice` daemon, SIP provisioning via caps, spatial channel per region + P2P/group channels; Lumiya used a separate plugin APK. Current = **WebRTC**: LL release 7.1.9 (2024-08-13, https://releasenotes.secondlife.com/viewer/7.1.9.10325451220.html) "adds WebRTC as the primary voice provider… replacing the dated Vivox-based system"; wiki https://wiki.secondlife.com/wiki/WebRTC_Voice — self-hosted per-region voice servers, ad-hoc/group pool, **no separate SLVoice exe for WebRTC, no voice morphing, no P2P bridging between WebRTC-only and Vivox-only viewers**. Code: viewer WebRTC module + `secondlife/3p-webrtc-build`; LibreMetaverse has both `.Voice.WebRTC` and `.Voice.Vivox`. OpenSim grids use Vivox (where licensed), FreeSWITCH/mumble modules, or the new Janus WebRTC addon seen in OpenSim master commits (2026, *index* via opensimulator.org dev page) — three mutually incompatible voice worlds; a mobile client must negotiate from `SimulatorFeatures`/region voice cap, not assume.
4. **Physics (server-side, affects client prediction/vehicle code):** SL = **Havok** (closed). OpenSim = pluggable: **BulletSim** (Bullet via native bridge, default in many configs, varregion support), **ubODE** (Ubit Umarov's ODE fork, now default in recent OpenSim, needs `ubODEMeshmerizer`), legacy **ODE/OpenDynamicsEngine**, `basicphysics`/POS (null). Mesher (`Meshmerizer` vs `ubODEMeshmerizer`) must match physics engine or collisions silently mismatch. Client-visible consequences: prim physics shapes, vehicle behaviour, raycast results differ SL↔OpenSim↔engine — never tune vehicle/physics constants against OpenSim alone.

### Priority cross-check stack for a mobile viewer (Lumiya / React-Linkpoint: TypeScript + Kotlin/Java + C# LibreMetaverse)

Ordered — for any given bug, check in this order and stop at the first disagreement:

1. **Packet/message definition wrong?** → `secondlife/master-message-template` `message_template.msg` **diffed against** `secondlife/viewer/indrallmessage` shipped template → LibreMetaverse `.Protocol` generated packets → Lumiya-Redux's 477 Java message classes. (Template flags — zerocoded, deprecated — are the trap.)
2. **Cap missing/renamed/changed payload?** → `secondlife/viewer` `llviewerregion.cpp:buildCapabilityNames` + `llaisapi.cpp:getCapNames` → wiki Current Sim Capabilities → LibreMetaverse caps code → Lumiya `SLCapability` enum.
3. **LLSD parsing (TS/Kotlin)?** → LibreMetaverse.StructuredData semantics + viewer `llsdserialize.cpp` test vectors → `@caspertech/llsd` (TS) / Lumiya Java LLSD → `secondlife/python-llsd` as a third vote. Watch binary/base64, dates, UUID, 64-bit ints.
4. **Login/session/teleport flow?** → LibreMetaverse login + TestClient (runnable C# oracle you can packet-capture) → viewer `llstartup.cpp` → Lumiya login/OkHttp code. Test against **local OpenSim standalone** (breakpointable server) and **Aditi**, in that order.
5. **Inventory/AIS/COF?** → viewer `llaisapi.cpp` + `llinventory*` → LibreMetaverse Inventory manager/examples (InventoryExplorer) → OpenSim inventory service (where it diverges, SL wins for Agni work).
6. **Mesh/texture/PBR/EEP/BoM rendering?** → viewer `llmeshrepository`, `lltexturecache`, GLTF material + EEP code → Firestorm (second implementation) → LibreMetaverse MeshFoundry/ModelFormats for geometry parsing in isolation → Lumiya-Redux gap analysis for what mobile GLES can realistically skip.
7. **TS layer specifically:** `CasperTech/node-metaverse` is the only TS client base verified — treat it as a *porting aid*, with LibreMetaverse as the semantic oracle for anything it lacks. **Kotlin:** no library exists — the Kotlin layer is necessarily a port of Lumiya Java / LibreMetaverse C#; keep generated message/LLSD code generated (from the template/YAML), never hand-edited.
8. **LSL content the viewer must compile/edit/preview:** signatures from `lsl-definitions` YAML only; lint via tailslide/lslint semantics; never execute OSSL assumptions on Agni.
